# SmartPI Dashboard 0.5.0

Reliable observation views, clearer SmartPI explanations and hardened chart-option merging.

## Changes

- Decode VTherm's published safety, power-shedding and manual/automatic window
  states, including bypass. Old unknown observations remain unknown.
- Three compact suspension tracks below temperatures, aligned with the chart's
  time axis, with explicit local-notebook provenance and an accessible table.
- Preserve valid Twin information when selecting another room. Discard previews
  and report uncertainty after reconnecting during an in-flight request, without
  automatically sending another thermostat command.
- Respect archived units throughout events, projections, tracking and technical
  details. Stop curves and thermal phases at long gaps or context/unit changes.
- Restore recorded Kp, Ki and integral state in historical replay. Optional
  separate PI-memory charts use archived data only and are created on demand.
- Explain published integral-hold, FF2-transfer and learning reasons. Transactions
  retain their own verified timestamp and requested/applied amounts in command
  percentage points. Missing data, unknown codes and unreliable tau stay explicit.
- Recover orphan notebooks after sensor removal or renaming. Admin-only inventory,
  consultation and explicit deletion free capacity without creating anonymous rooms.
- Harden uPlot 1.6.32's copied/merged options during reproducible builds: reject
  reserved prototype keys and inherited properties; only recurse into owned
  destination properties. The pinned upstream source is verified before patching.
  This addresses CodeQL alert #5 without suppressing the rule or dismissing the alert.

## Installation and data

Home Assistant **2026.11.0+**, SmartPI Diagnostics v2 and administrator access.
Update the custom **Integration** repository in Marketplace, restart Home Assistant,
then reload the panel. The compiled bundle and third-party notices are included.

The existing bounded private observation store is preserved. Suspension metadata
is collected prospectively; no past suspension is reconstructed from today's state.
The admin metadata API keeps its closed action list. A GET without an entity only
returns the bounded orphan inventory. No new thermostat service, schedule, tuning
or calibration is added; Apply remains required for temperature/preset changes.

## Verification

TypeScript, Node security/regression tests, Home Assistant Python tests,
reproducible build and full browser fixtures cover desktop/mobile, light/dark,
keyboard, missing/zero/stale data, gaps, archives and interrupted requests.
Check the workflows and CodeQL analysis on the release commit for remote results.
Synthetic tests do not certify physical accuracy or general accessibility.
